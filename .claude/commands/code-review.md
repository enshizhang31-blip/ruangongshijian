# Code Review Command - 代码审查命令

> 扫描未提交的代码改动，进行安全与质量审查，CRITICAL/HIGH 级别问题必须阻断合并

## 执行流程

### 1. 获取未提交改动

使用 git 命令获取当前的改动：
- `git diff --staged` - 已暂存的文件
- `git diff` - 未暂存的文件
- `git status` - 查看整体状态

### 2. 调用 code-reviewer agent

使用 Agent 工具调用 code-reviewer 进行代码审查：

```
任务：执行代码安全与质量审查

请对当前未提交的代码改动进行审查，包括：
1. 扫描所有改动文件（git diff --staged 和 git diff）
2. 按照项目规则进行检查：
   - 编码风格规则 (.claude/rules/coding-style.md)
   - 安全规则 (.claude/rules/security.md)
   - 测试规则 (.claude/rules/testing.md)
3. 输出结构化报告，按严重程度分类
```

### 3. 输出审查报告

```
## 代码审查报告

### 改动概览
- 已暂存文件：X 个
- 未暂存文件：X 个

### 问题汇总

| 严重程度 | 数量 | 阻断合并 |
|----------|------|----------|
| CRITICAL | X    | ✅ 是    |
| HIGH     | X    | ✅ 是    |
| MEDIUM   | X    | ❌ 否    |
| LOW      | X    | ❌ 否    |

### 详细问题

#### CRITICAL（必须修复）
1. **[文件:行号] 问题描述**
   - 规则：
   - 建议：

#### HIGH（建议修复）
...

#### MEDIUM/LOW
...
```

### 4. 阻断合并判断

**CRITICAL 和 HIGH 级别必须阻断合并**

```
---

## 审查结论

🚫 **阻断合并** - 存在 CRITICAL/HIGH 级别问题

请修复以下问题后重新审查：
1. [问题1]
2. [问题2]

---
```

或

```
---

## 审查结论

✅ **通过审查** - 无 CRITICAL/HIGH 级别问题

代码可以合并。

---
```

## 执行规则

1. **全面扫描**：必须检查所有未提交的文件改动
2. **严格评级**：按照规则准确定性问题级别
3. **CRITICAL/HIGH 阻断**：只要存在 CRITICAL 或 HIGH 级别问题，必须阻止合并
4. **清晰报告**：报告必须包含具体文件、行号和修复建议
5. **不修改代码**：审查只负责发现问题，不负责修复
