# Plan Command - 计划确认流程

> 在修改代码前，先复述需求、列出风险与步骤，并等待确认后再改代码

## 执行流程

### 1. 复述需求

**任务**：用自己的话重新描述用户的需求，确保理解正确。

```
## 需求复述

我理解你的需求是：
1. [需求点 1]
2. [需求点 2]
3. [需求点 3]

请确认以上理解是否正确。
```

### 2. 分析风险

**任务**：识别实现过程中的潜在风险。

```
## 风险分析

| 风险项 | 影响程度 | 缓解方案 |
|--------|----------|----------|
| 风险 1 | 高/中/低 | 方案 |
| 风险 2 | 高/中/低 | 方案 |
```

### 3. 列出步骤

**任务**：将需求拆解为具体的实施步骤。

```
## 实施步骤

1. **步骤 1**：xxx
   - 文件：
   - 改动：

2. **步骤 2**：xxx
   - 文件：
   - 改动：

3. **步骤 3**：xxx
   - 文件：
   - 改动：
```

### 4. 等待确认

**任务**：在获得用户确认前，不进行任何代码修改。

```
---

## 等待确认

请回复 "确认" 或 "可以" 后，我将开始实施。

如需调整，请告诉我具体修改意见。
```

## 执行规则

1. **不修改代码**：在获得用户确认前，禁止创建、修改或删除任何文件
2. **完整复述**：确保每个需求点都被理解并复述
3. **诚实评估风险**：不隐瞒潜在问题
4. **明确步骤**：每个步骤都要说明具体文件和改动内容
5. **等待确认**：用户确认是继续的唯一触发条件
