# Build-Fix Command - 增量构建修复

> 增量修复构建错误：修一个错误、跑一次构建，确保不引入新错误

## 核心原则

**一次只修一个错误，避免连锁反应**

## 执行流程

### 1. 分析错误

```
## 步骤 1: 分析错误

运行构建命令，查看错误信息：
- 识别第一个/最上面的错误
- 定位错误文件和行号
- 分析错误原因
```

### 2. 修复一个错误

```
## 步骤 2: 修复一个错误

针对第一个错误：
- 找到根本原因
- 进行最小改动修复
- 不尝试同时修复多个错误
```

### 3. 运行构建验证

```
## 步骤 3: 运行构建

修复后立即运行构建：
- 检查当前错误是否解决
- 检查是否引入新错误
- 确认构建成功后再处理下一个错误
```

## 增量修复示例

```
1. 运行 mvn compile
   → 错误1: Cannot find symbol UserMapper
   → 错误2: Cannot find symbol saveUser

2. 修复错误1（UserMapper）
   → 检查：缺少 @Mapper 注解
   → 修复：添加 @Mapper 注解

3. 运行 mvn compile
   → 错误1: 已解决 ✓
   → 错误2: 仍然存在

4. 修复错误2（saveUser）
   → 检查：方法名不匹配
   → 修复：重命名为 save

5. 运行 mvn compile
   → 构建成功 ✓
```

## 执行规则

1. **一次只修一个**：不同时修复多个错误
2. **修复后必验证**：每次修复后必须运行构建
3. **顺序处理**：按错误出现顺序，从上到下修复
4. **最小改动**：只改必要代码，不做无关修改
5. **记录进度**：每个错误修复后说明状态

## 构建命令参考

```bash
# 后端构建
mvn clean compile      # 编译
mvn clean package      # 打包
mvn test              # 运行测试

# 前端构建
pnpm run dev          # 开发
pnpm run build        # 生产构建
```

## 交互流程

```
1. 用户：帮我修复构建错误

2. 我：
   ## 构建修复

   运行构建中...
   错误列表：
   1. 错误1描述
   2. 错误2描述

3. 修复错误1
   → 运行构建...
   → 结果：错误1已修复，检查错误2

4. 修复错误2
   → 运行构建...
   → 结果：构建成功 ✓

5. 完成修复
```

## 注意事项

- 如果修复后出现新错误，可能引入了回归，需要回退
- 不要删除代码来"修复"错误
- 不要忽略警告，它们可能变成错误
- 如果某个错误修复困难，记录并继续处理其他错误
