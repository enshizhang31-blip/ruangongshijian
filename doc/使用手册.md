## 1. 项目概览

### 1.1 项目目标

SaleManager 是一套面向企业的销售管理平台，由 **三个端** 组成：

| 端 | 技术栈 | 用途 |
|----|--------|------|
| **Backend** | SpringBoot 2.7 + MyBatis-Plus + JWT | 统一 API 服务（Web 端 + 小程序端共用） |
| **Fronted** | Vue 3 + Vite + Arco Design + Pinia + Tailwind | 内部员工使用的 Web 管理后台 |
| **Uniapp** | uni-app + Vue 3 + uni-ui + vue-i18n | 面向终端用户（C 端会员）的小程序 |

### 1.2 核心模块

| 模块 | 说明 | 数据落地 |
|------|------|----------|
| 商品管理（SPU + SKU + SN 码） | 三层商品体系，支持规格、库存、批量导入 | MySQL |
| 客户/会员管理 | 会员等级、余额、积分 | MySQL |
| 订单管理 | 创建、支付、退款 | MySQL |
| 数据统计 | 销售概览、趋势图表 | MySQL |
| 权限控制 | 动态路由 + 权限数组（数据库驱动） | MySQL |
| 多语言支持 | UI + 业务翻译（MySQL + MongoDB + Redis） | MongoDB |
| 用户端商城 | 商品浏览、购物车、下单、多语言切换 | 调用上述所有模块 |

### 1.3 目录结构

```
SaleManagerSys
├── Backend/                # 后端项目 (SpringBoot)
├── Fronted/                # Web 管理端 (Vue3)
├── Uniapp/                 # 用户端小程序 (uni-app)
├── doc/                    # 项目文档
│   ├── api/                # API 接口文档（Web 端 + 小程序端）
│   ├── 使用手册.md         # 当前文件
│   ├── 功能完成度.md        # 各模块的实现进度
│   ├── 演示版启动指南.md    # 演示场景快速启动
│   └── ...

├── init-database.ps1       # 数据库一键初始化脚本（PowerShell）

```

## 3. 启动步骤

### 3.1 启动顺序

完整启动顺序：**① 启动数据库容器 → ② 初始化数据库结构 → ③ 启动后端 → ④ 触发业务数据初始化 → ⑤ 启动 Web/小程序**

---

### 3.2 启动数据库容器

在项目根目录执行：

```powershell
# 启动 MySQL + MongoDB + Redis 三个容器
cd Backend
docker compose up -d
```

第一次启动时容器会自动执行 `sql/schema.sql`、`sql/seed-data.sql`、`sql/mongo-init.js`。

> 💡 也可以直接执行仓库根目录的 `init-database.ps1`，它会重建并初始化（适合从零开始）。

### 3.3 初始化数据库结构

方式一：使用 PowerShell 一键脚本（**推荐**）

```powershell
# 在仓库根目录执行
.\init-database.ps1
```

该脚本会：
- 删除并重建 MySQL、MongoDB 容器
- 执行 `sql/init.sql` 创建表结构
- 输出表清单

方式二：手动执行（可选）

```bash
# 进入 MySQL 容器执行 SQL
docker exec -i salemanager-mysql mysql -uroot -proot123 sale_manager < sql/init.sql
```

### 3.4 启动后端服务

```powershell
cd Backend
.\mvnw.cmd spring-boot:run
# 或在 IntelliJ IDEA 中直接运行 BackendApplication
```

**默认 profile = local**，监听 `http://localhost:8080`

后端启动后会自动：
- seed 一个 **超级管理员** 账号（`admin` / `123456`，参考脚本输出日志）
- seed 小程序演示账号（`demo` / `123456`）

### 3.5 一键初始化业务数据

后端启动后，浏览器访问或 curl 调用：

```
GET http://localhost:8080/api/admin/system/data/init
```

可选 API（追加数据）：

```
POST http://localhost:8080/api/admin/system/data/append?module=customer&count=20
```

> ⚠️ 初始化 API 默认需要登录态，开发阶段如遇 401，参考 [8. FAQ](#8-常见问题-faq)。

### 3.6 启动 Web 管理端

```powershell
cd Fronted
npm install
npm run dev
```

默认地址：`http://localhost:5173`

### 3.7 启动小程序（演示版）

```powershell
cd Uniapp
npm install
npm run dev:h5              # H5 浏览器演示（最简单）
# 或
npm run dev:mp-weixin       # 微信小程序（需用微信开发者工具导入 dist/dev/mp-weixin）
```

### 3.8 健康检查

| 检查项 | 命令 / 地址 |
|--------|-------------|
| MySQL 容器运行中 | `docker ps \| findstr salemanager-mysql` |
| MongoDB 容器运行中 | `docker ps \| findstr salemanager-mongo` |
| Redis 容器运行中 | `docker ps \| findstr salemanager-redis` |
| 后端服务已起 | `curl http://localhost:8080/api/admin/auth/current` 返回 401 即表示服务在线 |

### 4.3 商品管理操作流程

#### 4.3.1 创建商品（SPU）

1. 进入「商品管理」→ 点击 **新增 SPU**
2. 填写：名称、选择分类、品牌、上传主图、描述
3. 保存后状态为「下架」
4. 继续添加 SKU：

#### 4.3.2 添加 SKU（三种方式）

- **单个添加**：选择 SPU → 「新增 SKU」→ 选规格组合 + 价格 + 成本价
- **批量生成**：在 SPU 详情页 → 「批量生成 SKU」→ 勾选多个规格值 → 系统计算笛卡尔积
- **SKU 编码建议**：使用 `{SPU 简写}-{规格值}-{规格值}`，如 `IP15-BLK-256`

#### 4.3.3 录入 SN 码（实物编号）

1. 进入「SN 码管理」→ 找到对应 SKU → 「录入 SN 码」
2. **三种录入方式**：
   - 单个录入：手动输入 SN 编号 + 关联 SKU
   - 批量导入：下载 CSV 模板 → 上传 → 预览 → 确认
   - 扫码录入（`/sn/scan`）：用 @zxing/browser 调用摄像头扫二维码/条形码
3. **库存自动计算**：`库存 = 状态=在库(0) 的 SN 码数量`

#### 4.3.4 上架 SPU

状态切换有两种方式：
- SPU 列表 → 「上架」按钮（一键）
- SPU 详情 → 编辑状态

**前置条件**：至少有一个启用且库存 > 0 的 SKU，否则用户看不到也无法下单。

### 4.4 客户（会员）管理

| 操作 | 入口 | 用途 |
|------|------|------|
| 列表/新增/编辑/删除 | `/customer` | 客户资料维护 |
| 余额调整 | 详情 → 「调整余额」 | 加 / 减余额，写入 `customer_balance_log` |
| 积分调整 | 详情 → 「调整积分」 | 加 / 减积分，写入 `customer_points_log` |
| 余额/积分明细 | 当前为 P1（待开发） | - |

会员等级自动计算：

| 等级 | 升级门槛（累计消费） | 折扣 |
|------|---------------------|------|
| 普通 | 0 | 100% |
| 银卡 | ≥ 1000 | 95% |
| 金卡 | ≥ 5000 | 90% |
| 钻石 | ≥ 20000 | 85% |

### 4.5 订单管理

进入 `/sale` 可查看订单列表，详情含商品明细。

当前实现的订单状态：

| 状态 | 状态码 | 可操作 |
|------|--------|--------|
| 待付款 | 0 | 支付、取消 |
| 已付款 | 1 | 退款申请 |
| 已完成 | 2 | - |
| 已取消 | 3 | - |
| 退款中 | 4 | 审核 |
| 已退款 | 5 | - |

> ⚠️ 发货（填物流信息）和退款审核功能已在 API 层预留，但前端交互待完善。

### 4.6 多语言翻译管理

#### 4.6.1 统一翻译编辑页（`/i18n/editor`）

适用对象：**所有实体类型**（商品、分类、规格、未来新增类型）。

字段类型驱动渲染：

| field_type | 表单控件 | 说明 |
|------------|----------|------|
| `text` | 单行 Input | 商品名、分类名 |
| `rich_text` | 多行 Textarea / 富文本 | 描述 |
| `number` | 数字输入（只读） | 数值（跨语言一致） |
| `boolean` | Switch（只读） | 布尔（跨语言一致） |
| `array` | Tag 编辑器 | 标签 / 营销标签 |
| `object` | 动态子表单 | JSON 对象（如可选颜色列表） |

#### 4.6.2 翻译状态总览（`/i18n/status`）

展示每个实体在各语言的完成度（`completeness = 已翻译数 / 总单元数 × 100%`）。

#### 4.6.3 后端可控上线/下架语言

只需编辑 `Backend/src/main/resources/application.yml`：

```yaml
i18n:
  supported-locales:
    - zh-CN
    - en-US
    - ja-JP
    # - ko-KR     # 注释即下线
```

重启后端 → 前端「我的」页面语言列表自动更新。

#### 4.6.4 数据流

```
请求 /api/goods/1  Header: X-Locale: en-US
   ↓
后端查 Redis 缓存
   ↓ 未命中 → MongoDB 查 translation_units
   ↓ 逐单元 fallback 解析 + 组装
   ↓ 返回多语言数据
```

### 4.7 员工与权限管理

> 进入 `/admin/user`。

| 操作 | 说明 |
|------|------|
| 列表 | 查看所有员工（含角色、最近登录时间） |

## 7. 常见功能操作流程

### 7.1 上架一个全新商品

```
1. 新建分类（如果不存在）→ 路径：商品管理 → 分类
2. 新建规格值（如 颜色:黑/白/金、容量:128G/256G/512G）→ 路径：商品管理 → 规格
3. 新建 SPU → 路径：商品管理 → SPU → 新增
4. 批量生成 SKU → SPU 详情 → 批量生成
5. 逐个设置 SKU 价格和成本价
6. 为每个 SKU 录入 SN 码（CSV 导入或自动生成）
7. 上架 SPU → SPU 列表 → 上架
```

### 7.2 调整商品价格

路径：商品管理 → SKU 列表 → 编辑价格

> 已生成但未支付的订单不受影响。

### 7.3 SN 码退货处理

```
1. 用户在小程序提交退款申请
2. 该订单涉及的 SN 码状态由 1（已售）变更为 3（退货中）
3. 货物入库后，状态变更为 4（已退货）→ 自动重新计入库存
```

### 7.4 SPU 下架

路径：商品管理 → SPU 列表 → 下架

- 用户端不再展示该 SPU 及其 SKU
- 已有订单不受影响
- 可随时重新上架

### 7.5 多语言新增一门语言

```
1. application.yml: i18n.supported-locales 添加（如 "ko-KR"）
2. 数据库脚本：为所有 translation_units 插入新 locale 空 entry
3. MongoDB: 建立该语言的 text 索引
4. 前端：locales/ 创建 ko-KR 目录并翻译 UI 文案
5. 重启后端 + 刷新前端
```

### 7.6 新增员工（操作员）

```
1. 系统管理 → 员工管理 → 新增
2. 选择角色模板（自动复制权限和路由）
3. 设置用户名、密码、姓名、手机号、邮箱
4. 保存 → 立即生效
```

## 8. 常见问题 FAQ

### Q1：后端启动失败，提示"Cannot find main class"
**A**：使用项目自带的 mvnw：`cd Backend && .\mvnw.cmd spring-boot:run`，不要使用系统 Maven。

### Q2：数据库初始化 API 返回 401
**A**：需要先登录获取 Token。开发阶段可临时在 SecurityConfig 中放行 `/api/admin/system/**`，或先登录后携带 Bearer Token 调用。

### Q3：Docker 容器端口被占用
**A**：检查 `docker ps` 占用端口，编辑 `docker-compose.yml` 修改宿主机端口（如 `3307:3306`），同步修改 `application-local.yml`。

### Q4：MySQL 连接失败
**A**：检查容器状态：`docker ps | findstr salemanager-mysql`，若未运行执行 `docker compose up -d mysql`。

### Q5：MongoDB 没有翻译数据，提示集合不存在
**A**：重启 MongoDB 容器（会自动执行 `mongo-init.js`）：
```bash
docker compose restart mongodb
```

### Q6：小程序编译报 "Could not find files"
**A**：确保在 `Uniapp` 目录执行 `npm install`，且 Node 版本 ≥ 20.19。

### Q7：小程序无法连接后端
**A**：
- 微信开发者工具：勾选「不校验合法域名」
- H5 模式：浏览器需允许跨域
- 修改 `Uniapp/src/utils/request.js` 的 `baseURL`

### Q8：Web 端打包后空白页
**A**：检查 nginx 配置是否正确转发到 index.html。如使用 Vite Preview 直接访问应正常。

### Q9：登录后立刻被踢出
**A**：JWT 有效期为 24 小时，检查 `application.yml` 中 `jwt.expiration`。

### Q10：如何重置数据
**A**：两种方式：
```powershell
# 方式一（推荐）：清空业务数据，保留表结构
.\clean-database.ps1
# 然后重新调用 http://localhost:8080/api/admin/system/data/init

# 方式二：从零开始
.\init-database.ps1   # 重启容器 + 重新建表
```

### Q11：演示订单造不出来
**A**：在小程序订单列表空状态时点击红色「🎬 Demo」按钮；或手动清理 uni.storage 后再次尝试。
