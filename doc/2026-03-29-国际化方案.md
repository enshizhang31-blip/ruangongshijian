## 一、整体架构

### 1.1 混合数据库

| 数据库            | 用途         | 说明               |
| ----------------- | ------------ | ------------------ |
| **MySQL**   | 核心业务数据 | 商品、订单、客户等 |
| **MongoDB** | 多语言数据   | 商品翻译、分类翻译 |

```
MySQL (关系型)                    MongoDB (文档型)
┌─────────────────┐              ┌─────────────────┐

│ admin_user      │              │ ui_translations │  UI翻译(预留)
│ ...             │              │                 │
└─────────────────┘              └─────────────────┘
```

## 二、字段类型定义

### 支持的字段类型

| field_type     | 说明         | 数据结构                                            |
| -------------- | ------------ | --------------------------------------------------- |
| `text`       | 文本         | `{ value: "内容" }`                               |
| `number`     | 数字         | `{ value: 100 }`                                  |
| `select`     | 单选         | `{ value_id: "1", value: "选项1" }`               |
| `boolean`    | 布尔         | `{ value: true/false }`                           |
| `array`      | 多选（选项） | `{ items: [{value_id:"0", value:"选项1"}, ...] }` |
| `array_text` | 多文本       | `{ items: ["标签1", "标签2"] }`                   |

### 简化后的 custom_attrs 结构

每个自定义属性包含：field_key（字段标识）、field_type（类型）、field_name（字段名）、value（值）

```javascript
// 中文
{
  field_key: "battery",
  field_type: "select",
  field_name: "电池容量",
  value_id: "2",
  value: "3000mAh"
}

// 英文
{
  field_key: "battery",
  field_type: "select",
  field_name: "Battery",
  value_id: "2",
  value: "3000mAh"
}
```

所有翻译都在 goods_i18n 的 locales 下存储，不再单独建立字段定义表。

### 价格计算规则

| 字段         | 说明                                                   |
| ------------ | ------------------------------------------------------ |
| `currency` | 货币类型（CNY/USD/EUR/JPY等）                          |
| 价格存储     | 价格存储在 MySQL `sku` 表的 `price` 字段（人民币） |
| 汇率存储     | 汇率存储在 Redis 缓存，定时任务从 Frankfurter API 更新 |

> 📌 关联说明：价格存储在 SKU 表而非 SPU 表，因为每个规格组合（SKU）有不同的价格。详见 [数据库设计.md - SKU规格表](doc/2026-03-28-数据库设计.md#13-sku规格表)

**计算公式**：

```
目标货币价格 = 人民币价格 × 目标货币汇率
例如：6999 CNY × 7.2 = 999 USD
```

**价格获取流程**：

```
1. 用户请求 /api/goods/1，Header: X-Locale: en-US
2. 后端查询 MySQL `sku` 表，获取 price（人民币）
3. 获取汇率（从 Redis 缓存获取，缓存未命中则调用 API）
4. 计算：price × 汇率 = 最终价格
5. 返回：{ price: 999, currency: "USD" }
```

**汇率更新机制**：

```
定时任务（每1小时执行）：
1. 调用 Frankfurter API: GET https://api.frankfurter.app/latest?from=CNY
2. 获取汇率：{ USD: 0.138, EUR: 0.128, JPY: 20.5 }
3. 存入 Redis，键名：exchange_rate:CNY
4. 缓存有效期：2小时
```

## 四、API设计

### 4.1 Header传递语言

```javascript
# 所有需要多语言的API统一使用Header
Header: X-Locale: zh-CN  (可选，默认zh-CN)
```

### 4.2 小程序端API

```javascript
# 商品列表
GET /api/goods
Header: X-Locale: zh-CN

# 商品详情
GET /api/goods/{id}
Header: X-Locale: zh-CN
响应: {
  id: 1,
  image_url: "...",
  price: 6999,
  name: "iPhone 15 Pro",           // 从MongoDB获取翻译
  description: "苹果最新款智能手机", // 从MongoDB获取翻译
  custom_attrs: [...]              // 从MongoDB获取翻译
}

# 分类列表
GET /api/category
Header: X-Locale: zh-CN
```

### 4.3 Web管理端API

```javascript
# 获取商品（含所有翻译）
GET /api/admin/goods/{id}
响应: {
  id: 1,
  base: { price: 6999, ... },
  i18n: {
    "zh-CN": { name: "...", description: "...", custom_attrs: [...] },
    "en-US": { name: "...", description: "...", custom_attrs: [...] }
  }
}

# 保存商品翻译（单个语言）
PUT /api/admin/goods/{id}/i18n/zh-CN
Body: {
  name: "iPhone 15 Pro",
  description: "...",
  custom_attrs: [...]
}

# 批量保存翻译
PUT /api/admin/goods/{id}/i18n
Body: {
  "zh-CN": { name: "...", description: "..." },
  "en-US": { name: "...", description: "..." }
}

# 获取分类翻译
GET /api/admin/category/{id}/i18n
PUT /api/admin/category/{id}/i18n
```

### 汇率获取方案

使用 **Frankfurter** API（完全免费，无需注册）：

```javascript
// 请求汇率（以CNY为基准）
GET https://api.frankfurter.app/latest?from=CNY

// 响应
{
  "amount": 1.0,
  "base": "CNY",
  "date": "2026-03-29",
  "rates": {
    "USD": 0.138,
    "EUR": 0.128,
    "JPY": 20.5
  }
}
```

**使用方式**：

- 每次请求商品时实时获取汇率
- 或定时任务缓存汇率（如每小时更新一次）
- 汇率缓存键：`exchange_rate:CNY:USD`
