## 一、整体架构

### 1.1 混合数据库

| 数据库            | 用途         | 说明               |
| ----------------- | ------------ | ------------------ |
| **MySQL**   | 核心业务数据 | 商品、订单、客户等 |
| **MongoDB** | 多语言数据   | 统一翻译单元集合 |

### 1.2 数据分布

```
MySQL (关系型)                    MongoDB (文档型)
┌─────────────────┐              ┌──────────────────────────────┐
│ goods           │              │ translation_units            │
│ goods_category  │              │                              │
│ spec_name       │              │  统一翻译单元集合:            │
│ spec_value      │              │  goods:1:name → { locales }  │
│ sku             │              │  goods:1:desc → { locales }  │
│ order           │              │  category:1:name → {locales} │
│ customer        │              │  spec:1:name → { locales }   │
│ admin_user      │              │  spec:1:value_1 → {locales}  │
│ ...             │              │                              │
└─────────────────┘              └──────────────────────────────┘
```

### 1.3 核心设计理念：最小翻译单元

> **一切可翻译的业务内容都是"最小元"（Translation Unit），由统一字段类型约束。**

- 商品名称是 1 个最小元，商品描述是 1 个最小元，每个自定义属性是 1 个最小元
- 分类名称是 1 个最小元，规格名称是 1 个最小元，每个规格值是 1 个最小元
- **一个实体 = 一组最小元的集合**，新增实体类型无需新建集合
- **UI 文案**（按钮、提示等）不走 MongoDB，仅用前端本地 `locales/*.json` 管理，见 [第七章](#七前端-ui-翻译)

## 二、最小翻译单元类型体系

### 2.1 单元结构（Translation Unit）

每个最小元是最小的可翻译单位，有且仅有一个 `field_type`，所有语言的翻译值存储在其 `locales` 中。

```javascript
// 一个最小元的完整结构
{
  _id: ObjectId,
  unit_key: "goods:1:name",            // 全局唯一标识，格式: {entity_type}:{entity_id}:{field_path}
  entity_type: "goods",                // 实体类型: goods | category | spec
  entity_id: 1,                        // 关联 MySQL 实体 ID（ui 类型为 0）
  field_path: "name",                  // 逻辑路径，如 name / description / attrs_material / value_3
  name: "商品名称",                     // 人类可读的名称，管理端展示用
  description: "商品的正式名称，用于列表和详情页标题",  // 字段说明，帮助运营理解每个最小元的含义
  field_type: "text",                  // 字段类型（见下方）
  sort_order: 0,                       // 在实体内的展示排序
  base_locale: "zh-CN",                // 基准语言
  base_content_hash: "sha256-xxx",     // 基准语言内容哈希（检测过时）
  locales: {
    "zh-CN": {
      value: "iPhone 15 Pro",
      status: "approved",              // draft | translated | approved
      updated_at: ISODate("2026-05-15")
    },
    "en-US": {
      value: "iPhone 15 Pro",
      status: "draft",
      updated_at: ISODate("2026-05-14")
    }
  },
  created_at: ISODate("2024-01-01"),
  updated_at: ISODate("2024-01-15")
}
```

### 2.2 字段类型体系（field_type）

| field_type | 说明 | value 存储类型 | 示例 | 前端渲染 |
|-----------|------|---------------|------|----------|
| `text` | 单行文本 | `string` | `"iPhone 15 Pro"` | `<Input>` |
| `rich_text` | 富文本/长文本 | `string` (HTML) | `"<p>最新款智能手机</p>"` | `<Textarea>` 或富文本编辑器 |
| `number` | 数字 | `number` | `6999` | `<InputNumber>` |
| `boolean` | 布尔值 | `boolean` | `true` | `<Switch>` |
| `array` | 文本数组 | `string[]` | `["热销","新品"]` | `<Select multiple>` 或 Tag 编辑 |
| `object` | JSON 对象 | `object` / `array` | `[{"vid":"0","v":"黑色"}]` | 动态表单（按子 schema 渲染） |

### 2.3 unit_key 命名规范

```
格式: {entity_type}:{entity_id}:{field_path}

实体级字段:
  goods:1:name                    # 商品1的名称
  goods:1:description             # 商品1的描述
  goods:1:short_desc              # 商品1的短描述
  category:1:name                 # 分类1的名称
  category:1:description          # 分类1的描述
  spec:1:name                     # 规格1的名称（如"颜色"）

自定义属性字段:
  goods:1:attrs_material          # 商品1的自定义属性-材质
  goods:1:attrs_battery           # 商品1的自定义属性-电池
  goods:1:attrs_colors            # 商品1的自定义属性-可选颜色
  goods:1:attrs_tags              # 商品1的自定义属性-标签

规格值字段:
  spec:1:value_1                  # 规格1的第1个值（如"黑色"）
  spec:1:value_2                  # 规格1的第2个值（如"白色"）
```

> **注意**：UI 文案（按钮、提示等）不使用 `translation_units`，仅用前端本地 `locales/*.json` 管理。不要为 UI 文案创建 `ui:*` 的最小元。

### 2.4 组装：从最小元到实体翻译

一个实体 = 查询该实体所有最小元 → 按 locale 合并：

```java
// 输入: entity_type="goods", entity_id=1, locale="en-US"
// 输出: { name: "iPhone 15 Pro", description: "Latest...", attrs: {material: "Titanium", ...} }

public Map<String, Object> assembleEntity(String entityType, Long entityId, String locale) {
    List<TranslationUnit> units = mongoTemplate.find(
        Query.query(Criteria.where("entity_type").is(entityType)
            .and("entity_id").is(entityId))
            .with(Sort.by(Sort.Direction.ASC, "sort_order")),
        TranslationUnit.class
    );

    Map<String, Object> result = new LinkedHashMap<>();
    Map<String, Object> attrs = new LinkedHashMap<>();

    for (TranslationUnit unit : units) {
        Object value = resolveLocaleValue(unit, locale);  // fallback + 类型还原
        String path = unit.getField_path();

        if (path.startsWith("attrs_")) {
            attrs.put(path.substring(6), value);          // attrs_material → material
        } else {
            result.put(path, value);
        }
    }
    if (!attrs.isEmpty()) result.put("attrs", attrs);
    return result;
}
```

### 2.5 字段类型校验规则

| field_type | 校验规则 |
|-----------|----------|
| `text` | 非空字符串，最大 500 字符 |
| `rich_text` | 字符串，最大 50000 字符 |
| `number` | 有效的 Number 类型，不校验范围（由业务层处理） |
| `boolean` | 必须是 true 或 false |
| `array` | 必须是数组，元素必须全是字符串，最多 100 项 |
| `object` | 必须是合法的 JSON（object 或 array），最大 100KB |

**跨语言一致性校验**（仅对以下类型）：
- `number`：所有 locale 的 value 必须数值相等
- `boolean`：所有 locale 的 value 必须相同
- 不校验 `text`/`rich_text`/`array`/`object`（不同语言自然不同）

## 四、价格与汇率（不变）

> 价格和汇率方案与旧版一致。价格仍存储在 MySQL `sku.price`（人民币），汇率通过 Frankfurter API + Redis 缓存换算。

| 字段 | 说明 |
|------|------|
| 价格存储 | MySQL `sku` 表 `price` 字段（人民币） |
| 汇率来源 | Frankfurter API（免费） |
| 汇率缓存 | Redis，键名 `exchange_rate:CNY`，TTL=2h |
| 更新频率 | 定时任务每小时执行 |

**价格获取流程**：

```
1. 用户请求 /api/goods/1，Header: X-Locale: en-US
2. 后端查询 MySQL sku 表，获取 price（人民币）
3. 获取汇率（Redis → 未命中 → Frankfurter API）
4. 计算：price × 汇率 = 最终价格
5. 返回：{ price: 999, currency: "USD" }
```

### 5.4 翻译 Fallback（降级）策略

```
请求 zh-TW → 缺失 locale → fallback zh-CN → fallback en-US → 返回空字符串
```

**实现**：每条最小元独立 fallback，而非整个实体：

```java
public Object resolveLocaleValue(TranslationUnit unit, String requestedLocale) {
    // 1. 尝试请求语言
    LocaleValue lv = unit.getLocales().get(requestedLocale);
    if (lv != null && lv.getValue() != null) return lv.getValue();

    // 2. 按 fallback 链逐个尝试
    for (String fallback : fallbackChain.get(requestedLocale)) {
        LocaleValue flv = unit.getLocales().get(fallback);
        if (flv != null && flv.getValue() != null) return flv.getValue();
    }

    // 3. 最终降级到默认语言
    LocaleValue dlv = unit.getLocales().get(defaultLocale);
    return dlv != null ? dlv.getValue() : "";
}
```

### 5.5 翻译缓存策略

| 缓存维度 | Key 格式 | TTL | 说明 |
|----------|----------|-----|------|
| 单个最小元 | `i18n:unit:{unit_key}` | 1小时 | 精确查询 |
| 实体翻译(单语言) | `i18n:entity:{type}:{id}:{locale}` | 1小时 | 客户端请求 |
| 实体翻译(全语言) | `i18n:entity:{type}:{id}:all` | 1小时 | 管理端编辑 |
| 翻译状态 | `i18n:status:{type}:{id}` | 30分钟 | 管理端状态面板 |

**缓存失效**：保存时直接 `DEL` 相关 key：

```java
public void evictEntityCache(String entityType, Long entityId) {
    String pattern = "i18n:entity:" + entityType + ":" + entityId + ":*";
    Set<String> keys = redisTemplate.keys(pattern);
    if (keys != null && !keys.isEmpty()) redisTemplate.delete(keys);
}
```

### 5.6 翻译一致性校验

| 校验项 | 适用 field_type | 规则 | 错误码 |
|--------|----------------|------|--------|
| 类型匹配 | 全部 | 值类型必须匹配 field_type | `TYPE_MISMATCH` |
| 必填 | text, rich_text | 基准语言的 value 不能为空 | `VALUE_REQUIRED` |
| 数值一致 | number | 所有 locale 的 value 必须相等 | `VALUE_DIVERGED` |
| 布尔一致 | boolean | 所有 locale 的 value 必须相等 | `VALUE_DIVERGED` |
| 数组元素类型 | array | 所有元素必须是字符串 | `ARRAY_ELEMENT_TYPE` |
| JSON 有效性 | object | 必须是合法 JSON | `INVALID_JSON` |

## 八、数据迁移方案

### 8.1 MySQL → translation_units

```java
@Component
@Order(1)
public class I18nDataMigrationRunner implements CommandLineRunner {

    @Override
    public void run(String... args) {
        if (isMigrationDone()) return;

        migrateGoodsToUnits();
        migrateCategoriesToUnits();
        migrateSpecsToUnits();

        markMigrationDone();
    }

    private void migrateGoodsToUnits() {
        List<Goods> goodsList = goodsMapper.selectList(null);
        for (Goods goods : goodsList) {
            // 为每个可翻译字段创建一个最小元
            createUnit("goods", goods.getId(), "name", "text", goods.getName(), 0, "商品名称", "商品正式名称");
            createUnit("goods", goods.getId(), "description", "rich_text", goods.getDescription(), 1, "商品描述", "商品详细描述，支持富文本");
            // short_desc
            if (goods.getShortDesc() != null) {
                createUnit("goods", goods.getId(), "short_desc", "text", goods.getShortDesc(), 2, "短描述", "商品简短描述，用于卡片展示");
            }
            // custom_attrs 如果有
            int order = 3;
            for (CustomAttr attr : goods.getCustomAttrs()) {
                String fieldPath = "attrs_" + attr.getFieldKey();
                createUnit("goods", goods.getId(), fieldPath, attr.getFieldType(), attr.getValue(), order++,
                    attr.getFieldName(), attr.getFieldDesc());
            }
        }
    }

    private void createUnit(String entityType, Long entityId, String fieldPath,
                            String fieldType, Object zhValue, int sortOrder,
                            String name, String description) {
        TranslationUnit unit = new TranslationUnit();
        unit.setUnitKey(entityType + ":" + entityId + ":" + fieldPath);
        unit.setEntityType(entityType);
        unit.setEntityId(entityId);
        unit.setFieldPath(fieldPath);
        unit.setName(name);
        unit.setDescription(description);
        unit.setFieldType(fieldType);
        unit.setSortOrder(sortOrder);
        unit.setBaseLocale("zh-CN");

        LocaleValue zhCN = new LocaleValue(zhValue, "approved");
        unit.getLocales().put("zh-CN", zhCN);
        for (String loc : List.of("en-US", "ja-JP")) {
            unit.getLocales().put(loc, new LocaleValue(null, "draft"));
        }

        translationUnitRepo.save(unit);
    }
}
```

### 8.2 新增语言流程

```
1. application.yml: supported-locales 添加新语言（如 "ko-KR"）
2. 批量脚本：为所有已存在的 translation_units 插入空 locale entry
3. MongoDB: 创建新语言的 text index
4. 前端: locales/ 目录创建 ko-KR/，复制 en/ 结构并翻译
5. UI: 语言切换菜单添加 "한국어"
```

### 8.3 新增实体类型流程

```
1. 定义该实体类型的 unit_key 命名规则（如 "brand:{id}:name"）
2. 无需修改任何 MongoDB 集合、Repository、Service——自动兼容
3. 前端翻译编辑器自动支持（选择 entity_type 即可）
```
